## 이번 세션에 한 일

### 1. 인덱스 정합 복구 — ExtSync 가 멈춰 있던 진짜 원인 (v3.8.7)

집 PC 안정경로(`%LocalAppData%\D102LabelExtension`)가 **v3.6.1(07-14)에 멈춰 있었다.**
확장 자체는 크롬에 정상 등록돼 있었고 D102 프로그램도 돌고 있었다.

원인: **`c08c5ea`(작업B slice 2b, skin.js)와 `7c13555`(저널·락, background.js)이 SHELL 파일을
바꾸고도 manifest 버전을 안 올리고 `build-shell-index.ps1` 을 안 돌렸다.** 그래서
`shell-files.json` 의 해시가 디스크와 어긋났고 ExtSync 가 내려보낼 판단을 못 했다.
→ v3.8.7 로 정합을 맞췄다. **SHELL 파일을 건드리면 반드시 버전 올림 + 인덱스 재생성.**

> ⚠ 인덱스 해시는 **텍스트=CRLF→LF 정규화 후 sha256, 바이너리(png)=원본 바이트**다.
> 전부 LF 정규화해서 대조하면 아이콘이 항상 STALE 로 보인다(이번에 한 번 오판했다).

### 2. 계정전환 로그인 fail-closed 커밋 (`7d196e4`)

07-22 공동검수 P1 3건이 미커밋 상태로 남아 있던 것을 검증 후 커밋했다. 캡차는 제출 없이
중단(P1-1), 제출 직전 id·pw 함께 재확정 + read-back 검증(P1-2), 정확명 두 필드가 같은 form 에
없으면 fail-closed(P1-3).

### 3. 작업B 결함 6건 수정 — 적대적 검수 4라운드 (`c0ce12e`)

**"작업B 는 코드 완성이라 게이트만 켜면 된다"는 판정이 반증됐다.** Codex 적대적 검수가
최초 6건, 재검수에서 3건을 더 잡았다. 커밋 메시지에 라운드별 전체 목록이 있다. 특히:

- **행 idx ≠ modify() 인자여도 그냥 진행**했다 → iframe 은 A 를 열고 검증·행교체는 B 를
  대상으로 삼을 수 있었다. fail-closed 로 바꿨다.
- **2차에서 내가 회귀를 넣었다** — `if (cls === 'save') st.dispatched = true` 를 지웠다.
  save 엔드포인트 도착은 가장 확실한 dispatch 증거인데 그걸 버렸다. 되살렸다.
- **3차는 내 설계 지시가 틀렸다** — `beforeunload` 를 제출 신호로 쓰라고 했는데, 그건 모든
  이탈에서 난다. 단순 내부이동이 저장 실패로 보였다. `valuesDirty` 판별자를 추가했다.
- **4차는 그 fix 의 fail-open** — 비교 불가를 '변경 없음'으로 단정했다. 3상태로 바꿨다.

> **교훈: 소스 문자열 존재만 확인하는 테스트는 조합 버그를 못 잡는다.** 2차 회귀가
> 정확히 그랬다. 판정 로직은 순수 함수로 뽑아 **실제 실행**하는 테스트를 붙일 것.

## ⚠ 알고 미룬 것 — C-2b 에서 반드시 처리

### 1. 작업B 가 계정 전역 writer lock·저널에 참여하지 않는다

설계 §5 는 **A·B·C 전부** 계정 전역 exclusive writer lock 에 참여하라고 요구한다.
작업B 는 지금 참여하지 않는다. `skin.js` 작업B 블록 상단에 주석으로 표시해 뒀다.

**유예 근거**: 작업B 는 네이티브 수정폼을 패널로 옮긴 것이라 HTTP 쓰기 표면이 늘지 않는다
(두 탭 lost-update 는 지금 네이티브 ERP 에도 존재한다). 락의 유일한 상대는 아직 없는 C 이고,
락 API 가 C 가 도입할 job/controller 모델에 묶여 있어 지금 배선하면 B 쪽 프로토콜을 두 번
설계하게 된다.

**그래도 남는 실제 구멍**(검수가 지적했고 인정한 것): 확장이 **성공 oracle 을 새로 추가**했다.
탭1 이 A→B 로 바꿔 저장했는데 실패하고, 그 사이 탭2 가 같은 주문을 B 로 저장했다면, 탭1 의
재조회값이 B 라서 **자기 저장이 성공한 것으로 오인**한다. 최종 서버값이 사용자 의도와 같아
추가 쓰기 피해는 없지만 "이 제출이 성공했는가"는 거짓이다. **계정 전환 중 저장도 차단되지
않는다** — 이쪽이 진짜 위험이고 C-2b 의 계정 가드와 함께 닫아야 한다.

### 2. 값이 안 바뀐 `form.submit()` 이 login/other 로 착지하면 무시된다

단순 이탈과 구분할 수 없어서 생긴 트레이드오프(3차 fix 의 대가). 변경값이 없어 정합성
피해는 없고, 사용자는 다음 동작에서 로그인 화면을 만난다. 주석에 남겨 뒀다.

### 3. node 테스트로 iframe·이벤트 통합 시나리오는 못 덮는다

`epDecideLoadAction` 등 순수 판정은 전 조합 실행 테스트로 고정했지만, iframe load →
`beforeunload` → `routeOk` → `epShowMsg` 까지 이어지는 실제 이벤트 순서는 실행하지 않는다.
스펙 §7 이 "브라우저 통합 검증(node 로는 못 잡는다)"으로 이미 분리해 둔 항목 → 라이브 검증 몫.
