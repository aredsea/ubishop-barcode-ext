### 3.2 🔴 남은 결함 1건 — 다음 세션의 첫 작업

**로컬 Codex 3라운드 [P1] — `src/masterprice.js:738-741`**

```js
const w = appendPriceLog(Object.assign({ status: 'pending' }, base));
if (!w.ok) {
  return { ok:false, status:'not_applied', logId:null, reason:'처리 로그 기록 실패 — …' };  // ← 여기는 중단한다
}
const r = await processOneItem(iframe, item.seq, priceFormatted, timeoutMs, (before) => {
  const upd = updatePriceLog(w.id, { before: before });
  if (!upd) log('write-ahead before 갱신 실패(목록 표시값은 남아 있음):', item.seq);   // ← 로그만 찍고 클릭이 진행된다
});
```

pending 항목 추가는 성공했는데 **`before`(실제 폼 원본) 갱신이 실패**하면(localStorage 용량 등),
로그만 남기고 **저장 클릭이 그대로 나간다.** 그러면 남는 건 목록 표시값뿐인데, 목록을 띄운 뒤 다른
사람이 그 상품을 고쳤다면 **그건 우리가 실제로 덮어쓴 원본이 아니다.** 되돌릴 유일한 근거가 유실된
채로 운영 데이터를 쓰는 경로다. 바로 위 분기는 같은 상황에서 제대로 중단하므로 **규율에서 한 곳만
빠진 것**이다.

**고칠 것**: `updatePriceLog` 실패를 콜백 밖으로 전달해 **클릭 전에 `not_applied` 로 중단**하라.
회귀 테스트도 붙여라(`updatePriceLog` 를 실패시키는 가짜 storage → 클릭 0회 확인).

### 3.4 3라운드에서 고친 것 (검수자 브리프에 그대로 넣어라)

| 코드 | 조치 |
|---|---|
| G1 | 배치 중단 알림 시도 건수 오프바이원 — `failedAt+1` → `failedAt+2`. 문구를 **"성공 확인 N건 / 확인 필요 1건 / 미시도 M건"** 으로 분리(확인 필요 상품이 '미시도' 에 안 섞이게) |

## 6. 이번 세션에서 비싸게 배운 것

- **`v.price` vs `v.value` 는 글자 수가 같다.** 변이/치환 검증을 **길이 비교**로 하면 조용히
  no-op 이 되고 "테스트 통과" 라는 **위음성**이 난다. 내가 실제로 당했다(처음엔 "치환 실패" 로 오독).
  **내용 비교로 확인하라.** 참고로 `src/masterprice.js`·`tests/masterprice.test.js` 는 **LF** 이고,
  `src/content.js` 등 기존 파일은 **CRLF** 다 — 개행 가정도 파일마다 다르다.
- **정적 문자열 대조 테스트는 뚫린다.** 작업 1의 첫 테스트는 if/else **블록 안**만 봐서, `else` 의
  호출을 둔 채 **블록 뒤에** 호출을 추가하면(=실패해도 체크가 풀리는 바로 그 버그) 그냥 통과했다.
  작업 2도 같은 이유로 안전장치 변이 6종이 SURVIVED 했다. **실행 하네스로 바꿔라.**
- **그 전환이 실제 버그를 하나 끄집어냈다.** `runBulkUpdate` 가 `v.value` 를 읽는데
  `validateBulkInput` 은 `{ok,count,price}` 를 반환 → `undefined` → `formatComma(undefined)` =
  **문자열 `"NaN"`** 이 적용시세에 저장될 뻔했다. **Opus·Codex·Fable 세 검수자가 모두 놓쳤다.**
  읽어서는 안 보이고 **돌려야** 보이는 종류였다.
- **테스트가 "절대 실패할 수 없는" 상태일 수 있다.** G6 의 N2 테스트는 지연 alert(15ms)보다
  단언이 먼저 실행돼 원본과 변이가 구별되지 않았다. **통과는 신호가 아니다 — 변이를 넣어 죽는지 봐야
  통과가 의미를 갖는다.**
- **검수자 셋은 서로 다른 것을 본다.** 1라운드에서 "가격 0 저장" 경로는 Fable·Codex 만 잡았고
  Opus 는 못 봤다. 2라운드 오프바이원은 Opus·Fable 이 잡고 Codex 는 안 냈다. **겹치지 않는다.**
- **크롬 렌더러가 죽는다.** 라이브 ERP 를 MCP 로 조사하다 `Runtime.evaluate` 가 45초 타임아웃
  나며 탭이 무응답이 됐다(직전 세션 인수인계에도 같은 증상 기록). 조사 결과는 **그때그때 spec
  §0 에 적어 둬라** — 다시 못 볼 수 있다.
- **큰 검수 라운드는 세션 한도를 먹는다.** 이번 세션이 그래서 중단됐다. 3종 병렬 검수를 여러 라운드
  돌릴 거면 라운드 사이에 한도 여유를 확인해라.
