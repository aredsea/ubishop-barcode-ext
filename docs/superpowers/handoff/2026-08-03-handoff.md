## 이번 세션에 한 일

### 근본원인 — 비고 재정렬이 **한 번도 실행된 적이 없었다**

직전 세션(v3.9.9)이 "비고를 맨 위로" 를 구현했는데 라이브에서 `.ub-ep-outer` 가 **0개**였다.
`epReflowLayout` 에 "바깥 배치표에 rowspan 이 하나라도 있으면 물러난다" fail-safe 가 있고,
그 표는 **썸네일 칸이 항상 `rowspan=2`** 다. 즉 매번 걸렸다. 사장님이 본 "엉망인 안쪽 UI" 는
옵션표만 2열로 압축된 ERP 원본이었다.

→ 가드를 **"입력을 품은 rowspan 칸만 거부"**(`epRowspanBlocks`)로 좁혔다. `tr` 을
`display:contents` 로 통과시키는 순간 rowspan 은 렌더링에 관여하지 않으므로, 표시 전용 칸의
rowspan 까지 거부하던 게 과보호였다.

### 세로 997 → 627px (실측 분해)

| 덩어리 | 크기 | 처리 |
|---|---|---|
| 비고 표 **빈 스페이서 행 9개** + gap | 177px | `.ub-ep-filler` 로 접음 |
| 썸네일 액자 `td.img_border` 의 **`height="160"` 속성** | ~120px | `height:auto` (이미지만 줄여선 안 줄어든다) |
| 상품정보 표 셀 `height`(28·48) + 여백 | ~115px | `height:auto` + 4px 패딩 |
| `textarea` — **`rows=4` 라 `min-height` 로는 안 줄어든다** | 21px×2 | 실제 `height:84px` (⚠`!important` 붙이면 리사이즈 손잡이가 죽는다) |

배치: `.ub-ep-outer` 를 **flex-wrap**(grid 아님 — 마지막 줄에 상품정보 `1 1 240px` + 썸네일
`0 0 auto` 를 나란히 두려면 필요). order = 비고1 · 옵션2 · 상품정보3 · 썸네일4(48px, **숨기지
않음** — 엉뚱한 주문을 눈으로 거르라는 사장님 결정). 비고 표는 2열 그리드, textarea 행만
반 칸 + 라벨을 값 위로(`.ub-ep-stack`).

### 패널 높이 자동 맞춤

자식이 콘텐츠 바닥을 재 `dataset.ubEpFit` 으로 알리고 부모가 맞춘다(`ubEpDone` 과 같은
same-origin DOM 방식, 세대 가드 동일). **높이는 더 이상 저장하지 않는다** — 저장하면 콘텐츠를
줄여도 옛 높이로 열려 "매번 늘리기" 증상이 그대로 남는다. 폭·위치는 계속 저장한다.

### 같이 고친 기존 버그 2건

1. `epClampPanel` 이 **백그라운드 탭**에서 패널을 420×320 으로 찌그러뜨렸다.
   `document.hidden` 이면 `innerWidth/innerHeight/screen` 이 **전부 0** 이라 `Math.min` 이
   음수를 골랐다. → 못 재면 손대지 않는다.
2. `.ub-epw` 에 **`box-sizing` 이 없어** clamp 마다 2px 씩 커졌다(`offsetWidth` 는 border 를
   포함하는데 그걸 `style.width` 에 되썼다). 내 변경이 clamp 횟수를 늘려 증폭시켰다.

## ★ 이번에 비싸게 배운 것 (다음 사람이 또 밟지 않게)

### 1. `!important` 끼리는 **특이도**로 갈린다 — 한 세션에 두 번 밟았다

- `.ub-ep-outer>tbody>tr>td`(클래스 1) 가 `.ub-ep-card .t_form td`(클래스 2) 에 져서
  padding 이 안 먹었다 → `.ub-ep-card table.ub-ep-outer>…` 로 클래스 수를 맞췄다.
- **`.ub-ep-filler{display:none}` 이 뒤에 선언된 `.ub-ep-row{display:grid}` 에 동률로 져서
  빈 행이 하나도 안 접혔다.** 순서에 기대지 않도록 `.ub-ep-card tr.ub-ep-row.ub-ep-filler` 로
  특이도를 올렸다(규칙을 아래로 옮기는 건 다음 사람이 또 순서를 바꾼다).

### 2. 라이브 검증 위양성 — 델타 CSS 를 **별도 `<style>` 로 나중에** 붙이지 마라

위 두 번째 결함을 내 라이브 확인이 통과시켰다. 델타를 별도 스타일시트로 뒤에 붙이니
**최종 단일 스타일시트의 선언 순서와 달라져** 우연히 이겼다. Codex 와 Fable 이 **독립적으로
같은 것**을 잡았다.
→ 대응: `tests/orderitem-editpopup.test.js` 에 **CSS 캐스케이드 승자 계산기**를 넣었다.
실측 DOM 사슬에 대해 `display` 의 최종 승자를 계산한다(콤마목록·자손·자식·태그+클래스·
`!important`·특이도·선언순서). 미지원 선택자(`:not()`·`[attr]`·`#id`·`+`·`~`)는 느슨화해
**걸릴 수 있으면 fail-closed 로 신고**한다. red-green 으로 확인했다 — 옛 규칙으로 되돌리면
`이긴 규칙: .ub-ep-card tr.ub-ep-row → display:grid` 로 실패한다.
**문자열 존재 검사로는 이 부류를 절대 못 잡는다.**

### 3. 높이 측정에 `scrollHeight` 를 쓰지 마라

뷰포트보다 작아지지 않는다. 실측: 패널 900/700/660 에서 `scrollHeight` 가 851/651/626 을
돌려줬고 **실제 콘텐츠는 내내 627** 이었다. 그걸 쓰면 패널이 절대 줄지 않고, 신호가 두 번
(rAF · load) 오는 동안 오히려 조금씩 커진다. → `epContentHeight()` 가 **body 자식들의 가장
아래 모서리**를 직접 잰다(패널 크기와 무관하게 같은 값). 못 재면 `scrollHeight` 폴백.

### 4. `shell-files.json` 해시 규약과 타이밍

- **텍스트 = CRLF→LF 정규화 / 바이너리(png) = 원본 바이트.** 섞으면 ExtSync 가
  all-or-nothing 으로 번들 전체를 거부한다. 정본 스크립트는 저장소의 `build-shell-index.ps1`.
- **재생성한 뒤 소스를 또 고치면 해시가 낡는다.** 커밋 직전에 재생성 + 독립 재검증할 것.
  (위 "다음에 할 일 2번" 이 이걸 자동화하자는 얘기다.)

### 5. 이 폼의 절대 불변식 (변함없음, 다시 확인함)

```
form1.elements.length = 48
form1 이 DOM 으로 품은 요소 = 0        ← 전부 밖
form1.id = (없음)
```
**노드를 옮기면 소유권이 재계산돼 끊기고 그 칸은 조용히 저장되지 않는다.**
재배치는 전부 CSS 로만. 이번 변경도 `classList` / `style.order` / `style.flex` / `dataset` 뿐이다.

## 남은 미검증 / 알려진 한계

- **최종 코드 라이브 재측정 미완** (위 "가장 먼저 할 일 1"). spec §4.4 의 627 은 반영 전 값이다.
  마지막 변경(`EP_ACTION_SEL`)은 컨트롤로 세는 범위를 **넓히기만** 해서 방향은 fail-safe 다
  — 잘못 숨기는 일은 늘지 않고 접히는 행이 줄어들 수만 있다. 두 검수자 모두 커밋 비차단 판정.
- `ubEditPopup` **기본 OFF** 유지. ON 을 기본값으로 올릴지는 라이브 재확인 후 사용자와 합의.
- 매장 PC 실제 수신 확인 안 됨(정책 폴링 ~5분, raw CDN 캐시). 매장에서 `[UB][skin] v4.0.0` 확인 필요.
- 프로그램(vpk) 릴리스는 하지 않았다 — 번들만 저장소에 맞춰 뒀다. 확장 갱신은 update.xml 경로가
  담당하므로 급하지 않다.
- 검증 세션 내내 **크롬 MCP 가 불안정**했다(탭 4회 소멸, 마지막엔 렌더러 무응답). 라이브 검증이
  필요한 작업은 시간 여유를 두고 시작하라.
