# 주문 수정 팝업 — 내부 UI 재설계 (2026-08-03)

주문 전표(`/jun/orderitem/orderItemList.do`)의 [수정] 팝업은 v3.9.9에서 **껍데기**(목록 위 플로팅
패널)를 완성했다. 이 문서는 그 **안쪽**을 다시 짠다.

> 사장님 지시(2026-08-03): *"팝업 자체는 개선이 됐는데, 안쪽 ui가 엉망이야. 그냥 있는대로 쓸려해도,
> 거기에 세로 크기가 디폴트로 잡혀있어서 매번 크기를 늘리거나 스크롤을 내려야해. 아예 안쪽 ui를
> 뜯어고쳐줘."*

## 1. 무엇이 문제였나 (2026-08-03 라이브 실측)

회사 PC 크롬(확장 3.9.9 로드됨)에서 주문 388077의 수정 팝업을 열어 측정했다.

| 증상 | 실측 | 원인 |
|---|---|---|
| 비고가 여전히 맨 아래 | `.ub-ep-outer` 0개, `.ub-ep-grid1` 0개 | **`epReflowLayout`이 통째로 bail-out** |
| 매번 늘리거나 스크롤 | 문서 높이 **958px** vs 기본 패널 660px | 콘텐츠가 기본 높이를 298px 넘김 |
| 여백 낭비 | 카드 916px 중 비고 224px·스페이서/구분선 다수 | ERP 원본 배치 + 라벨 78px 우측정렬 |

### bail-out의 정확한 원인

`epReflowLayout`에는 fail-safe가 있다.

```js
if (rows.some((tr) => Array.from(tr.cells).some((td) => td.rowSpan > 1))) {
  epLog('바깥 배치표에 rowspan 있음 → 순서 유지'); return;
}
```

바깥 배치표는 3행 4칸이고 **썸네일 칸이 `rowspan=2`** 다(실측 `r1c1 r2c1 / r1c2 / r1c2`).
그래서 매번 이 가드에 걸려 **비고 재정렬·썸네일 처리가 한 번도 실행된 적이 없다.**
즉 지금 화면은 "옵션표만 2열로 압축된 ERP 원본"이다.

가드 자체는 틀리지 않았다 — 표 레이아웃에서 rowspan은 그리드에 대응물이 없다. 다만 우리는
`tr`을 `display:contents`로 통과시키므로 **rowspan은 그 시점에 이미 의미가 없다**. 가드가
과보호였다.

### 절대 어기면 안 되는 제약 (실측 재확인)

```
form1.elements.length = 48
form1 이 DOM 으로 품은 요소 = 0        ← 전부 밖
form1.id = (없음)
```

이 폼은 HTML 중첩이 깨져 있어 **48개 컨트롤 전부가 DOM상 `form1` 밖**이고, 파서가 붙여준
암묵적 소유권으로만 연결돼 있다. 노드를 옮기면 그 소유권이 재계산되고 — 조상에 `form`이 없으니 —
**그 칸은 조용히 저장되지 않는다.** 라이브 ERP에서 사장님 수정분이 유실된다는 뜻이다.

→ **재배치는 전부 CSS로만 한다. 노드는 0개 옮긴다.** (사장님 결정: 노드 무이동 + CSS Grid)

## 4. 구현

### 4.1 `epReflowLayout` — rowspan 가드를 좁힌다

전면 거부 → **"컨트롤을 품은 칸이 rowspan이면 거부"**로 좁힌다.

```
rowspan 이 있는 칸 중 입력(input/select/textarea)을 하나라도 품은 칸이 있으면 → 종전대로 거부
그런 칸이 없으면(=썸네일처럼 표시 전용) → 진행
```

근거: `tr`을 `display:contents`로 통과시키는 순간 rowspan은 렌더링에 관여하지 않는다. 위험은
"묶여 있어야 할 입력이 흩어지는 것"인데, 그건 rowspan 칸이 입력을 품었을 때만 생긴다.
표시 전용 칸(사진)은 흩어져도 잃을 게 없다.

### 4.2 바깥 배치표 = flex-wrap + order

`.ub-ep-outer`를 grid → **`display:flex; flex-wrap:wrap`** 으로 바꾼다. 이유: 마지막 줄에서
상품정보(남는 폭 전부)와 썸네일(48px 고정)을 **한 줄에 나란히** 두려면 flex의 `flex:1` /
`flex:none`이 필요하다. grid는 칸 수를 미리 고정해야 해서 이 조합이 안 나온다.

칸별 지정 (`epReflowLayout`이 인라인 style로 부여):

| 칸 | order | flex |
|---|---|---|
| 비고+인도예정일 (textarea 보유 칸) | 1 | `0 0 100%` |
| 옵션표를 품은 칸 | 2 | `0 0 100%` |
| 나머지(상품정보) | 3 | `1 1 240px` |
| 썸네일 전용 칸 (입력 0 + `img[onclick*=imageView]`) | 4 | `0 0 auto` |

썸네일 칸은 이제 **숨기지 않는다**. `EP_THUMB_SEL` 판정은 그대로 쓰되 `display:none` 대신
order/flex만 준다.

### 4.3 비고 표 = 2열 그리드

`.ub-ep-grid1`을 1열 → **2열**(`repeat(2, minmax(0,1fr))`)로 바꾼다.

- textarea 행(주문비고·발주비고): 각각 **반 칸** 차지. `.ub-ep-full`을 붙이지 않는다.
  행 내부는 `grid-template-columns: minmax(0,1fr)`로 세워 **라벨을 값 위**에 올린다
  (78px 우측정렬 라벨을 반 칸에 두면 값이 뭉개진다).
- 그 외 행(고객인도예정일): `grid-column: 1 / -1` 전체 폭, 라벨은 종전대로 좌측 78px.
- 문서 순서가 주문비고 → 발주비고이므로 order 없이도 좌/우가 맞는다. 인도예정일은 `order:2`.

### 4.4 세로 압축

| 항목 | 지금 | 바꿈 |
|---|---|---|
| `textarea` min-height | 112px | **84px** (3행) |
| `.t_tab td/th` padding | 11px 10px | **6px 10px** |
| 썸네일 `img` width | 112px | **48px** |
| `.ub-ep-card` padding | 16px | **14px** |

예상: 958px → **약 600px** (패널 헤더 44px 포함 시 약 645px).

### 4.5 패널 높이 자동 맞춤

콘텐츠를 줄여도 "기본 660px에 안 맞으면 또 스크롤"이 남는다. 근본 해결은 **패널이 콘텐츠에
맞추는 것**이다.

- 자식(iframe 문서)이 `epDressPopup` 끝에서 `documentElement.scrollHeight`를 재어
  **자기 iframe 엘리먼트의 `dataset.ubEpFit`** 에 쓴다. 부모가 `MutationObserver`로 본다.
  → `ubEpDone`과 **같은 방식**이다(same-origin DOM only, postMessage 위조면 없음).
- 부모는 `높이 = clamp(320, 콘텐츠 + 헤더높이 + 2, innerHeight - 32)`로 패널 높이를 정하고
  `epClampPanel`을 다시 태운다.
- **높이는 더 이상 저장하지 않는다**(`ubEpH` 쓰기 중단, 읽기는 폐기). 폭·위치는 그대로 저장한다.
  이유: 저장된 높이가 있으면 콘텐츠를 줄여도 옛 높이로 열려 이 작업의 목적이 사라진다.
  사용자가 손으로 늘린 값은 **그 창을 닫을 때까지** 유효하다(리사이즈 핸들은 그대로 둔다).
- 자식이 신호를 못 보내면(구조가 달라 dress 실패 등) 종전 기본값 660px로 연다 — fail-safe.

### 4.6 손대지 않는 것

- 저장 경로(네이티브 `form1` 제출), `epWatchSubmit`, 세대(gen) 가드, `epReloadList` 선행 규칙
- `epCompactForm`의 옵션표 판정 로직(`known >= 3`, colspan/rowspan 거부) — 이 표는 rowspan이 없다
- 폼 뒤 블록 보존 규칙(저장 버튼·서버 오류 문구가 거기 있을 수 있다)

## 5. 검증

### 단위 (`tests/orderitem-editpopup.test.js` 확장)

1. `epRowspanBlocks()` — 입력 품은 rowspan 칸 → `true`(거부), 사진만 있는 rowspan 칸 → `false`(진행)
2. 실측 4칸 구조를 넣으면 order/flex가 `1,2,3,4`로 부여되는지
3. 썸네일 칸이 **`display:none`이 아닌지** (회귀: 이전엔 숨겼다)
4. 비고 표 2열 — textarea 행에 `.ub-ep-full`이 **안 붙는지**, 인도예정일 행엔 붙는지
5. `epFitHeight(content, headerH, viewportH)` 순수 함수 — clamp 경계(작은 콘텐츠·거대 콘텐츠·좁은 화면)

### 라이브 (회사 PC 크롬, 실제 주문)

- `.ub-ep-outer` / `.ub-ep-grid1`이 **1개 이상** 붙는지 (지금은 0)
- 비고 두 칸이 화면 최상단이고 가로로 나란한지
- 문서 높이 ≤ 660, 패널이 스크롤 없이 열리는지
- **`form1.elements.length === 48` 유지** — 재배치 전후로 소유권이 하나도 안 깨졌는지
- 저장은 누르지 않는다(라이브 데이터). 소유권 검사로 대신한다

### 게이트

Codex(read-only) 적대적 검수 + `fable-reviewer` 교차 검수. **양쪽 다 "문제없음"** 이어야 커밋.
