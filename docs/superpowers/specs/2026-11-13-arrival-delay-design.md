# 입고 지연 알림 · 목록 페이지 — 설계

- 작성 2026-11-13 · 대상: 확장 background + 새 확장 페이지 + popup (SHELL 채널)
- 요청(사장님): D102 FASHION 주문 중 **영업일 14일을 넘겨도 입고되지 않은 상품**을 따로 목록 페이지로 보여 주고, 크롬 알림으로 알려 준다.

## 1. 결정 사항 (사장님 확정)

| 항목 | 결정 |
|---|---|
| 기준 날짜 | **둘 다 따로** — 발주 전(주문완료·본사확인)은 **주문일**부터, 발주 후(발주완료)는 **발주일**부터 각각 14영업일 |
| 알림 시점 | **새로 지연된 건이 생길 때만** — 같은 건을 매일 다시 알리지 않는다 |
| 목록 위치 | **확장 전용 페이지**(새 탭) — 알림 클릭·팝업 버튼으로 연다 |
| 켜는 PC | **팝업 스위치로 켠 PC만**(기본 OFF) — 매장 PC 에 알림이 뜨지 않게 |
| 구현 방식 | **A. 확장 background 가 주기 조회** (B 유비샵 탭에서만 / C 트레이 프로그램 은 기각) |

## 2. 실측 사실 (2026-11-13, 읽기 조회)

- 목록: `POST /jun/orderitem/orderItemList.do?tcode=order_item`, 파라미터 `searchShop=LT`(FASHION), `searchItemStatus`, `searchDateType=a.orderDate`, `syear..eday`, `pageSize`(최대 500), `reqPage`, `searchSortType=seq`.
- 상태 코드: `O--` 주문완료 · `OS-` 본사확인 · `B--` 발주완료 · `I--` 입고완료 · `T--` 출고완료 · `TS-` 출고확인 · `S--` 판매완료 · `OC-` 주문취소.
- **미입고 = O--, OS-, B--** 세 상태. 2025-01-01~2026-11-13 FASHION: 주문완료 9 · 본사확인 0 · 발주완료 30 (가장 오래된 발주완료 10-27, 주문완료 09-21·09-23 — 발주 자체가 안 된 건 존재).
- 목록 헤더(14열 계정): `No | (체크) | 주문일·주문장번호 | 발주처명·발주일 | 이미지 | 매입처상품코드·상품코드 / 고객명 | 구분 | 상품정보 | 수량 | 주문가 | 매장명(주문직원) | 인도예정일 | 상태 | 수정/취소`. 13열 계정은 발주처명 열이 없다 → **열 위치는 헤더 글자로 찾는다**(기존 `oiJunListRows` 관례). 발주처명 열이 없으면 발주일을 알 수 없으므로 발주완료 건은 **주문일 기준 + '발주일 미확인' 표시**로 폴백.
- 날짜 셀 형식: `26-11-13` + 주문장번호 `0000002Z02` 가 붙어 온다. 발주처 셀: `키골드(F) 26-11-13`(발주 전이면 발주처명만, 날짜 없음).
- 공휴일: d102-atelier Edge 함수 `GET https://sshwwwavcbgyiyojngav.supabase.co/functions/v1/holidays?year=YYYY` → `{year, days:{"YYYY-MM-DD":"이름"}}`. **Origin 허용 목록**(`d102-atelier.vercel.app`·localhost·127.0.0.1)만 받고 그 밖은 403 — 확장 SW 의 fetch 는 `Origin: chrome-extension://kejfpekfhpjlaifonfdlegmnoglaaphf` 를 붙이므로 **허용 목록에 확장 ID 한 줄 추가 필요**(§7 승인 대기).

## 4. 데이터 흐름

1. **트리거**: `chrome.alarms` `ub-arrival` — 30분마다 깨어나 **영업시간(09:00~19:00, 로컬) 이고 마지막 성공에서 2시간 지났을 때만** 조회. 크롬 시작(`onStartup`)·스위치 ON 직후·목록 페이지의 [지금 다시 확인]은 즉시 조회. 스위치 OFF 면 아무 것도 안 한다.
2. **조회**: 상태 3개(O--, OS-, B--) × `searchShop=LT`, 기간 = 오늘−365일 ~ 오늘, pageSize 500, 순차 3회. 응답 URL 이 `ubshop.biz` 의 목록 경로가 아니면 **로그인 끊김**(기존 `assertUbdstore` 관례). 한 상태라도 500행이면 `capped` 표시.
3. **판정**(core): 행마다 `stage` = 발주 전(O--·OS-) / 발주 후(B--). 기준일 = 발주 전 → 주문일, 발주 후 → 발주일(없으면 주문일 + `baseFallback:true`). `elapsed` = 기준일 다음 날부터 오늘까지의 영업일 수(주말·공휴일 제외, 기준일 자체는 세지 않음). **`elapsed > 14` 이면 지연.**
4. **저장**: `chrome.storage.local.ubArrival = { at, ok, error, capped, holidaysOk, items:[…지연 행…] }`, 마지막 성공 결과는 실패해도 지우지 않는다(목록 페이지에 '마지막 성공 시각' 과 함께 보임).
5. **알림**: 알린 키 집합 `ubArrivalNotified` (키 = `orderSeq + '|' + stage`). 이번 지연 키 중 집합에 없는 것이 있으면 `chrome.notifications.create` 1회 — 제목 '입고 지연 새로 N건', 본문 '전체 M건 · 가장 오래된 것 K영업일'. 알린 뒤 집합 = (기존 ∩ 이번 지연) ∪ 새 키 — 지연에서 빠진 키는 버려서, 나중에 다시 지연되면(예: 발주 후 단계) 다시 알린다. 알림 클릭 → 목록 페이지 탭.
6. **배지**: 지연 건수 > 0 이면 액션 배지에 숫자(빨강). 0 이면 지운다. 기존 'NEW'(업데이트) 배지가 있으면 업데이트 배지를 우선한다.

## 5. 목록 페이지

- 머리: '입고 지연 (FASHION · 14영업일 초과) N건' · 마지막 확인 시각 · 상태 줄(로그인 필요 / 500행 잘림 / 공휴일 미반영) · [지금 다시 확인].
- 표(경과 영업일 내림차순): 단계(발주 전/발주 후) · 경과 영업일 · 주문일 · 발주일 · 발주처 · 상품명·코드 · 고객명 · 수량 · 상태 · 주문장번호.
- 주문장번호 클릭 → 유비샵 주문전표 새 탭. 주문장번호로 걸러 여는 GET 파라미터가 통하는지는 구현 때 실측하고, 안 되면 목록을 그냥 연다.
- 0건이면 '지연 없음'. 스위치가 꺼져 있으면 '팝업에서 입고 지연 알림을 켜세요'.
- 스타일은 기존 popup·패널과 같은 D102 브랜드 색(#35C5F0 계열, 기존 확장 관례) · 다크모드 금지 테스트 준수.

## 6. 오류 처리

- 로그인 끊김·네트워크 실패: 저장 결과의 `ok:false, error` 만 갱신, 알림 없음. 목록 페이지에 표시.
- 공휴일 조회 실패: 주말만 제외하고 계산, `holidaysOk:false` → 목록에 '공휴일 미반영(지연이 실제보다 늦게 잡힐 수 있음)'. 연도별 성공 결과는 storage 에 캐시(과거 연도 영구, 올해·내년 7일).
- 행 파싱 실패(헤더 못 찾음): 그 상태 조회를 실패로 보고 저장 결과에 남긴다 — 빈 목록을 '지연 없음' 으로 보이지 않게(fail-closed).
- 쓰기 요청은 하나도 없다(검색 POST·공휴일 GET 만).

## 7. 승인 필요 (외부 변경)

- **d102-atelier `supabase/functions/holidays/index.ts` 의 `ALLOWED_ORIGIN_HOSTS` 에 `kejfpekfhpjlaifonfdlegmnoglaaphf` 추가 + 함수 재배포.** 운영 Edge 함수라 사장님 확인 후 진행. 거절되면 확장 안에 2026~2027 공휴일 표를 넣고 연 1회 갱신하는 방식으로 대체.
